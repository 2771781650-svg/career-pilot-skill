# 技术架构

## 1. 分层

```
┌──────────────────────────────────────────────┐
│  表现层   web/index.html（零依赖 Web 界面）    │
│           main.py（命令行）                    │
├──────────────────────────────────────────────┤
│  服务层   server.py（标准库 HTTP + JSON API）  │
├──────────────────────────────────────────────┤
│  智能层   agent/react.py                       │
│           ├ 有 Key → ReAct 循环（LLM 自主决策） │
│           └ 无 Key → 规则路由（意图识别）        │
│           agent/memory.py 最近 6 轮记忆        │
│           agent/prompts.py 工具注入提示词      │
├──────────────────────────────────────────────┤
│  工具层   tools/  六个可插拔工具 + ToolRegistry│
├──────────────────────────────────────────────┤
│  数据层   data/jobs.jsonl  岗位库              │
│           data/questions.json 面试题库         │
└──────────────────────────────────────────────┘
```

## 2. ReAct 循环

```
用户问题
  ↓
LLM 输出 JSON：{"thought":..., "action":"analyze_resume", "action_input":{...}}
  ↓
ToolRegistry.run(action, input) → observation
  ↓
把 observation 拼回对话，再次请求 LLM（最多 4 步）
  ↓
LLM 输出 {"thought":..., "final":"..."} → 呈现给用户
```

关键设计：
- **严格 JSON 协议**，解析失败时正则兜底提取 `{...}`
- **步数上限 4**，防止无限调用工具烧 token
- **单步单工具**，保证每一步可解释、可复现
- LLM 调用异常 → 自动降级到规则引擎（`mode=rule_fallback`）

## 3. 规则路由（降级引擎）

按优先级做意图匹配，命中即调用对应工具：

| 优先级 | 触发条件 | 工具 |
|---|---|---|
| 0 | 含"生成/写/做/起草简历" | `build_resume` |
| 1 | 含"面试"且含"回答/点评"且长度 > 40 | `evaluate_answer` |
| 2 | 含岗位名 + 简历/匹配/投递 | `analyze_resume` → `match_job`（链式） |
| 3 | 含"简历/评估/体检/打分" | `analyze_resume` |
| 4 | 含"面试" | `interview_question` |
| 5 | 含"计划/规划/怎么学/路线" | `career_plan` |
| 6 | 都不命中 | 帮助文案 + 岗位清单 |

## 4. 核心算法

### 4.0 简历生成（`tools/resume_builder.py`）

```
技能 → 按 SKILL_DICT 的 6 个能力类别归类
经历 → 按分隔符切分，剔除指令性噪音，补 STAR 骨架（无数字则提示补结果）
目标岗位 → 自动注入该岗位 must/plus 关键词，供 HR 系统检索
缺项 → 生成"还差的材料"清单（联系方式/项目/技能/证书/岗位）
```

### 4.1 简历评分（`tools/resume.py`）

```
总分 = 学历分(20) + 技能分(40) + 项目分(20) + 经历分(10) + 证书分(10)
技能分 = min(40, 命中技能词数 × 5)
```

技能词典分 6 大类（视觉设计 / 视频剪辑 / 三维动效 / 前端开发 / 内容运营 / AI应用），
每类 10 余个关键词，命中即归类。缺口建议按优先级生成（学历 → 技能 → 项目 → 经历 → 量化 → 证书）。

### 4.2 岗位匹配（`tools/job_match.py`）

```
匹配度 = 100 × (硬性要求覆盖率 × 0.7 + 加分项覆盖率 × 0.3)
```

硬性要求权重高，因为缺失硬性技能通常直接过不了初筛。
输出三类清单：已具备硬性 / 缺失硬性 / 已具备加分，并给出补齐顺序。

### 4.3 STAR 点评（`tools/interview.py`）

```
得分 = 命中要素数 × 18 + 量化结果(10) + 篇幅合适(10)   # 上限 100
```

四要素各有关键词集（情境/任务/行动/结果），未命中项给出针对性改写建议。

### 4.4 路径规划（`tools/career.py`）

按每周小时数切分：主线 60% / 产出 30% / 复盘 10%，8 周内按"打基础 → 做产出 → 冲刺"三阶段推进，
每两周强制一个可交付物，避免"学了但没产出"。

## 5. 接口

`POST /api/chat`

```json
请求：{"question":"...", "history":[{"role":"user","content":"..."}]}
响应：{
  "answer": "最终回答",
  "steps": [{"thought":"...","action":"analyze_resume","input":{},"observation":"..."}],
  "mode": "llm | rule | rule_fallback",
  "engine": "规则引擎模式（无需 API Key）"
}
```

## 6. 安全与边界

- 只在本地 `127.0.0.1` 监听，不对外暴露
- API Key 只从环境变量读取，`.env` 已加入 `.gitignore`
- 不采集、不上传用户简历内容；无 Key 时全流程离线
- 工具执行异常统一捕获，返回可读错误而非崩溃
